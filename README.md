# فروشگاه دوستان 🎮

سایت فهرست بازی‌های PlayStation 4، PlayStation 5 و Xbox آفلاین — ساخته‌شده با Next.js، کاملاً فارسی و راست‌چین با فونت وزیرمتن. الهام‌گرفته از ظاهر hencheats.vercel.app با پس‌زمینه تیره، کاورهای عمودی و جستجوی زنده.

## امکانات

- صفحه اصلی با نمایش پیش‌فرض بازی‌های **PS5** و تب‌های PS5 / PS4 / Xbox آفلاین / همه
- جستجوی زنده (نام فارسی، انگلیسی و ژانر) و مرتب‌سازی (جدیدترین، نام، منتخب‌ها)
- کارت‌های بازی با کاور عمودی، نشان پلتفرم و ستاره «منتخب»
- پنل ادمین در `/admin` با ورود رمز، افزودن/ویرایش/حذف روزانه بازی
- **افزودن گروهی بازی با هوش مصنوعی** (تا ۳۰ بازی در هر اجرا) + پیدا کردن خودکار کاور رسمی از استورهای PlayStation/Xbox، Steam، RAWG، ویکی‌پدیا و جستجوی تصویر وب
- سه دسته PS4، PS5 و Xbox Offline + آپلود فایل کاور یا لینک کاور (کاور کاملاً اختیاری)
- ذخیره‌سازی: لوکال SQLite داخل پوشه `data/`، روی Vercel با Postgres (Neon)

## راه‌اندازی لوکال

```bash
npm install
npm run setup    # یک بار اجرا شود: نام کاربری و رمز عبور ادمین را می‌سازد و نمایش می‌دهد
npm run dev      # اجرای توسعه روی http://localhost:3000
```

برای اجرای پروداکشن لوکال:

```bash
npm run build
npm start
```

## پنل ادمین

- آدرس: `http://localhost:3000/admin`
- نام کاربری پیش‌فرض: `admin` و رمز در خروجی `npm run setup` چاپ می‌شود
- رمز را می‌توانید هنگام ساخت با متغیر `ADMIN_PASSWORD` تعیین کنید
- بعد از ۵ ورود ناموفق، ورود به مدت ۱۰ دقیقه قفل می‌شود
- کاور اختیاری است: می‌توانید خالی بگذارید، لینک https بدهید یا فایل JPG/PNG/WebP تا ۳ مگ آپلود کنید (فایل مستقیم داخل دیتابیس ذخیره می‌شود)
- کلیک روی هر ردیف در لیست، مستقیم آن بازی را وارد حالت ویرایش می‌کند

## افزودن گروهی بازی با هوش مصنوعی (AI Game Publisher)

در پنل ادمین، بخش «هوش مصنوعی — افزودن گروهی بازی»:

1. هر خط یک نام بازی بنویسید (انگلیسی، حداکثر ۳۰ بازی).
2. دکمه «تولید بازی‌ها» را بزنید؛ مدل `glm-5.3-flash` (سرویس APInex) برای هر بازی نام فارسی، پلتفرم، ژانر و توضیح فارسی می‌سازد.
3. کاور رسمی به این ترتیب از اینترنت پیدا و دانلود می‌شود (اولین منبعی که جواب دهد):

   `PlayStation Store` → `Xbox Store (API رسمی مایکروسافت)` → `Steam` → `RAWG (نیازمند RAWG_API_KEY)` → `ویکی‌پدیا` → `DuckDuckGo` → `Bing` → `Google`

4. هر فایل کاور در جدول `covers` ذخیره و از `/api/covers/<uuid>.<ext>` سرو می‌شود (همان مسیر آپلود دستی).
5. اگر بازی از قبل در فروشگاه باشد، رد می‌شود؛ ولی اگر آن بازی کاور نداشته باشد، در همان اجرا کاور برایش پیدا و اضافه می‌شود.
6. اگر کاوری پیدا نشد، بازی بدون عکس ذخیره می‌شود و هشدار می‌گیرید؛ با دکمه **Retry** (یا اجرای دوباره همان نام) دوباره تلاش می‌شود.

نکته‌ها:

- `APINEX_API_KEY` فقط سمت سرور خوانده می‌شود و هرگز به مرورگر نمی‌رود.
- هر بازی بسته به منابع کاور حدود ۱۰ تا ۳۰ ثانیه طول می‌کشد؛ درخواست‌ها دوتا-دوتا (concurrency = ۲) اجرا می‌شوند.
- روت تشخیصی کاور (فقط برای ادمین واردشده): `/api/admin/ai/cover-debug?name=Returnal`
  با `&keep=1` کاور پیدا‌شده در دیتابیس نگه داشته می‌شود، وگرنه ردیف موقت پاک می‌شود.
- پاک‌سازی کاورهای یتیم (ردیف‌هایی که هیچ بازی‌ای به آن‌ها وصل نیست):

  ```bash
  node scripts/clean-orphan-covers.mjs          # فقط گزارش
  node scripts/clean-orphan-covers.mjs --apply  # حذف واقعی
  ```

## استقرار روی Vercel (قدم‌به‌قدم)

> روی Vercel فایل‌سیستم ماندگار نیست، پس دیتابیس باید Postgres باشد. کاورهای آپلودی داخل خود دیتابیس (data-URL) ذخیره می‌شوند، پس جدا مشکلی ندارند.

1. **ساخت دیتابیس:**
   - در داشبورد Vercel پروژه را ایمپورت کنید، بعد بروید `Storage` → `Create` → `Neon Postgres` و به پروژه وصل کنید.
   - Vercel خودش متغیر `DATABASE_URL` را در Env ها می‌گذارد.

2. **ساخت متغیرهای ادمین:**
   ```bash
   node scripts/vercel-env.mjs "رمز-ادمین-دلخواه-حداقل-۶-کاراکتر"
   ```
   خروجی (`ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`, `COOKIE_SECURE=true`) را در
   `Vercel → Project → Settings → Environment Variables` (برای Production) کپی کنید.
   اگر قبلاً به Storage وصل شده‌اید، `DATABASE_URL` را دست نزنید.
   برای فعال شدن افزودن گروهی با AI، `APINEX_API_KEY` (و در صورت تمایل `AINEX_BASE_URL`, `AINEX_MODEL`, `RAWG_API_KEY`) را هم اضافه کنید.

3. **دیپلوی:**
   ```bash
   git push   # یا Deploy از داشبورد Vercel
   ```
   بیلد موفق یعنی `npm run build` سبز شده. جدول `games` و داده‌های اولیه (seed) در اولین بازدید خودکار ساخته می‌شوند.

4. **نکات مهم:**
   - اگر روی HTTPS هستید حتماً `COOKIE_SECURE=true` باشد (اسکریپت خودش true می‌گذارد).
   - `/api/admin/backup` برای گرفتن بکاپ JSON از بازی‌هاست.
   - اگر `DATABASE_URL` ست نباشد، سایت بالا می‌آید ولی داده‌ها فقط در حافظه موقت همان instance هستند (ماندگار نیستند).

## نکته‌های استقرار لوکال/سرور شخصی

- داده‌ها در پوشه `data/` (فایل `doostan.db`) نگه داشته می‌شوند؛ هنگام استقرار، این پوشه را ماندگار (volume) کنید.
- اگر روی HTTPS منتشر می‌کنید، در `.env.local` مقدار `COOKIE_SECURE=true` بگذارید.
- با متغیر `DOOSTAN_DATA_DIR` می‌توانید مسیر داده‌ها را تغییر دهید.

## تست

```bash
npx playwright install chromium   # یک بار
npm test
```

- تست‌های صفحه اصلی بدون تنظیمات اضافه اجرا می‌شوند.
- تست‌های پنل ادمین به رمز نیاز دارند؛ قبل از اجرا این دو متغیر را ست کنید:
  `E2E_ADMIN_USERNAME=admin` و `E2E_ADMIN_PASSWORD=رمز-ادمین` (اگر ست نشوند، آن تست‌ها skip می‌شوند).
- تست‌ها روی سرور پروداکشن (`npm start` روی پورت ۳۰۰۰) اجرا می‌شوند؛ پس قبلش `npm run build` بزنید.
